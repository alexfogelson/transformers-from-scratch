Embeddings

Inside a transformer, chapter 2

Look up each token’s vector

Each token id picks one column from a big learned table, the embedding table, and gets a copy of that column’s numbers. That copy is the token’s embedding. Nothing is computed: it’s a lookup. The table starts out as random numbers and is adjusted during training, like every other weight in the model.

Our model gets its position information later, inside attention (chapter 5). Older models like GPT-2 instead look up a second vector for each position here and add it on.

Normalisation

Inside a transformer, chapter 3

Bring every vector to the same size

Before attention, each token’s vector is rescaled to a standard length. This step is called RMSNorm, and it happens again before every attention and feed-forward block. Every layer adds onto the running vectors, so without it their sizes would keep drifting and attention scores would swing to extremes. Geometrically it’s two moves: slide every vector onto a sphere, then stretch the sphere.

This is a visualisation with d = 3 numbers per vector, so it can be drawn. In a real model each vector has d numbers (4,096 in Llama 3 8B) and lands on a sphere of radius √d in d-dimensional space: radius 64 for d = 4,096.

Rotary positions

Inside a transformer, chapter 4

Where position comes in

The embeddings carry no position information. Instead, inside every attention layer (step 4 of chapter 5), each token’s query and key are rotated by its position just before they’re compared. This is rotary position embedding (RoPE), used by Llama and most current models.

The rotary math, step by step

Playing with rotary

Inside attention, a query and a key are each cut into pairs of numbers, drawn here as arrows. Four of the 32 pairs are shown, from fastest to slowest. Each arrow is turned by its position times its pair’s speed. Blue is the query, orange the key, and the faint dashed arrows are where they pointed before turning. Watch the angle between them: it depends only on how far apart the two positions are.

Attention

Inside a transformer, chapter 5

Tokens share information

Attention is the only place where tokens look at each other. Each token works out what it’s looking for, compares that with what every earlier token offers, and gathers information from the best matches. Each vector here is drawn as a column of shaded cells; the numbers themselves don’t matter, only how they flow.

Feed-forward

Inside a transformer, chapter 6

Each token thinks on its own

After attention has mixed information between tokens, the feed-forward block processes each token by itself: widen the vector, bend it with a simple curve, and shrink it back. It holds most of a dense model’s parameters (about 80% of each layer in Llama 3 8B). Below the dense version is the mixture-of-experts version, which swaps this one block for several.

From a vector to a word

After the last layer, one final step turns the model’s running vectors into a choice: normalise, take the last position, score every token in the vocabulary, shape those scores into probabilities, and draw one.
